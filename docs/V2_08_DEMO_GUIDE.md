# V2-08 演示指南

本文档提供面试、录屏或项目展示时的完整演示方案。

## 合成演示资料

### 位置

`examples/demo_workspace/`

### 文件清单

| 文件名 | 类型 | 描述 |
|--------|------|------|
| `sales_survey_2025q2.csv` | CSV | 2025年Q2销售调查数据，包含地区、产品、销量、收入和评分 |
| `survey_incomplete.csv` | CSV | 含缺失值的调查问卷数据，用于测试数据质量检测 |
| `job_analysis_2025q2.xlsx` | XLSX | 多工作表岗位分析表（岗位对比、技能矩阵、投递记录） |
| `grading_rubric.pdf` | PDF | 课程数据分析报告评分标准（文本型PDF） |
| `analysis_standards.md` | Markdown | 数据分析项目规范文档，包含表格、代码块和清单 |

所有数据均为虚构合成，不包含真实个人信息或商业数据。当前 `examples/demo_workspace/` 目录包含 `README.md`（文件说明和推荐任务），实际演示文件需通过生成脚本或手动准备。图片演示文件（PNG/JPG，用于 OCR 测试）需用户自行添加。

## 推荐演示任务

### 任务1：销售数据分析

选择 `sales_survey_2025q2.csv`，输入：

> 分析各地区各产品的销售表现，找出最佳销售组合。

展示重点：多维度数据分析、Pandas 统计、Agent 路由到 `data_analysis_agent`。

### 任务2：数据质量检查

选择 `survey_incomplete.csv`，输入：

> 检查这份问卷数据的质量，指出缺失值和潜在问题。

展示重点：文件理解阶段的自动质量检测（缺失值、重复行、异常值），Profile 中的 `quality_issues` 字段。

### 任务3：岗位与技能对比

选择 `job_analysis_2025q2.xlsx`（多工作表），输入：

> 对比不同公司的岗位要求，与我的技能矩阵进行差距分析。

展示重点：多工作表 XLSX 解析、跨表格分析、`multi_table` 分类。

### 任务4：跨文件分析

选择 `sales_survey_2025q2.csv` 和 `grading_rubric.pdf`，输入：

> 根据评分标准，检查销售数据是否满足课程分析报告的要求。

展示重点：跨模态文件关联、文档检索 + 数据分析、`cross_source` 分类、关系发现。

### 任务5：规范文档检索

选择 `analysis_standards.md`，输入：

> 查询数据分析项目的质量检查清单和报告格式要求。

展示重点：Markdown 标题路径分块、文档检索、`document_research_agent`、RAG 引用定位。

## 完整演示流程

以下流程覆盖从注册到报告下载的完整闭环，预计 8-12 分钟。

### 第1步：注册与登录（1-2 分钟）

1. 启动应用后打开前端页面（隔离验收环境：`http://localhost:5173`）
2. 进入注册页面，输入受邀用户的注册信息（需有效邀请码）
3. 使用预设的管理员账号或注册的测试账号登录
4. 如使用临时密码登录，演示强制改密流程

### 第2步：创建工作区（30 秒）

1. 进入工作区列表页
2. 创建新工作区（例如命名为 "Q2 销售分析"）
3. 展示工作区概览（空状态）

### 第3步：批量上传文件（1 分钟）

1. 进入工作区 "文件" 子页
2. 批量上传 `sales_survey_2025q2.csv`、`grading_rubric.pdf` 和 `analysis_standards.md`
3. 展示逐文件的上传验证（扩展名、MIME、文件头、大小）
4. 展示 "已上传，待理解" 状态

### 第4步：文件理解（1 分钟）

1. 选择已上传的 3 个文件，点击 "批量理解"
2. 依次查看每个文件的 Profile：
   - CSV：显示字段列表、行数、列数、缺失值统计、数值统计、类型推断
   - PDF：显示页数、文本长度、分页结构
   - Markdown：显示标题层级、代码块数、分段结构
3. 展示各文件的质量问题标记和建议角色/标签
4. 确认或修改文件的角色和标签

### 第5步：文件关系发现（1 分钟）

1. 进入 "关系" 子页
2. 点击 "发现关系"
3. 展示自动发现的候选关系（例如 CSV 中的产品字段与 PDF 中的评分标准可能相关）
4. 确认一个关系，拒绝另一个，演示关系修正备注
5. 展示关系列表中的置信度、证据、类型和审计链

### 第6步：创建任务与计划确认（1-2 分钟）

1. 进入 "任务" 子页
2. 选择 `sales_survey_2025q2.csv` 和 `grading_rubric.pdf`
3. 输入任务4的文本："根据评分标准，检查销售数据是否满足课程分析报告的要求"
4. 提交任务草稿
5. 如果计划追问触发，回答追问信息
6. 查看 Supervisor 生成的计划草稿（步骤列表、Agent 分配、依赖关系）
7. 展示计划的版本化修改（添加/删除/重排步骤）
8. 确认计划

### 第7步：启动 Worker 并观察执行（1-2 分钟）

1. 启动 Worker 进程（隔离验收环境脚本已提供命令）
2. 确认任务被 Worker 认领
3. 通过 SSE 实时观察执行进度：
   - `file_understanding_agent`：读取文件 Profile
   - `data_analysis_agent`：执行预设 Pandas 分析
   - `document_research_agent`：检索 PDF 规则文档
   - `report_agent`：生成结构化报告
   - `quality_review_agent`：执行确定性质量检查
4. 展示 SSE 事件详情（步骤、状态、工具调用摘要、耗时）
5. 展示任务执行时间线

### 第8步：查看报告（1 分钟）

1. 任务完成后进入 "报告" 子页
2. 展示 Markdown 报告正文（安全渲染，包含章节导航）
3. 展示报告资产（图表、表格、附件）
4. 点击 "下载 Markdown"，展示下载
5. 尝试 "下载 DOCX" 或 "下载 PDF"（需 LibreOffice/Poppler）
6. 对报告点赞/点踩，输入反馈

### 第9步：数据隔离演示（30 秒）

1. 使用第二个浏览器或无痕窗口
2. 注册第二个用户（使用新邀请码）
3. 登录第二个用户
4. 确认看不到第一个用户的工作区、文件、任务和报告

### 第10步：管理员视角（30 秒）

1. 使用管理员账号登录
2. 查看 "管理" 页面
3. 展示运行治理信息（任务、Worker、模型、配额），注意不暴露用户正文和密钥
4. 展示清理 dry-run 输出

## 隔离环境启动步骤

使用隔离验收环境而非真实数据库，确保演示安全：

```powershell
# 1. 准备验证环境
powershell -File .\scripts\start_final_acceptance.ps1

# 这一步会：
#   - 创建 .runtime/final-acceptance/ 隔离目录
#   - 生成随机 AUTH_SECRET_KEY
#   - 运行 Alembic upgrade head（独立 SQLite）
#   - 创建临时管理员和邀请码
#   - 输出后端/Worker/前端启动命令

# 2. 在三个独立终端中分别启动后端、Worker 和前端
# （具体命令由 start_final_acceptance.ps1 输出）

# 3. 演示完毕后停止
powershell -File .\scripts\stop_final_acceptance.ps1

# 4. 完全清理（可选）
powershell -File .\scripts\clean_final_acceptance.ps1
```

## 无 OCR/DeepSeek 环境下的降级演示方案

如果演示环境缺少 Tesseract OCR 或 DeepSeek API Key，以下功能将受影响：

### OCR 降级

- 图片上传仍可成功
- 图片理解会标记 OCR 未配置/失败，Profile 的 `parser` 字段显示降级信息
- 演示时可说明："这是系统在 OCR 不可用时的明确降级提示，不会崩溃或返回错误数据"

### DeepSeek 降级

- 任务分类使用规则分类器（`classifier.py` 中的关键词/模式匹配）
- 文件理解不使用语义增强，只使用确定性解析
- RAG 回答使用模板拼接（检索结果 + 固定回答模板）
- 报告总结使用预设模板而非 LLM 生成

**降级演示同样有效**：因为项目设计本身就强调了"先做规则和工具，再接 LLM"的工程理念。降级模式是设计功能的一部分，不是 Bug。

## 面试演示重点展示项

面试官通常关注以下维度，建议在演示中有意侧重：

| 维度 | 展示方式 |
|------|----------|
| **不是聊天机器人** | 强调任务草稿 → 计划确认 → Worker 队列的流程；不同于 ChatGPT 一问一答 |
| **Agent 架构** | 展示 Supervisor + 五个专业 Agent 的步骤分配和工具调用记录 |
| **安全设计** | 展示文件扩展名/MIME/文件头三重校验、用户隔离、CSRF 双 Token、Argon2id 密码 |
| **可观测性** | 展示 SSE 事件流、执行时间线、工具调用日志、质量审核结果 |
| **工程结构** | 展示后端模块化（models/services/api/agents 分层）、前端组件化、Docker Compose |
| **降级设计** | 展示无 LLM 时的规则分类和模板回答仍可用，不会完全不可用 |
| **数据边界** | 展示 Workspace Context 只输出安全元数据（不含原始文件内容、用户密码、API Key） |

## 注意事项

- 演示文件不要包含真实隐私数据（所有 `examples/demo_workspace/` 文件均为虚构）
- 不要在演示时展示真实 `.env` 文件内容或 API Key
- 不要声称已部署到公网或已有真实用户（仓库未执行部署）
- 不要声称 SQLite 可支撑生产级并发
- deterministic 评估的 1.0 始终标注为规则自检，不描述为模型准确率
- 如果使用隔离验收环境，演示完毕后记得清理（临时密码不会保留）
