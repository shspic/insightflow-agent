# 项目效果评估说明

## 1. 数据分析结果评估

表格数据分析可以从以下角度评估：

- 行列数是否与原始 CSV / Excel 一致。
- 字段名是否完整读取，是否有乱码或空字段。
- 缺失值统计是否与原始数据一致。
- 数值列识别是否正确。
- 文本列识别是否合理。
- 日期列识别是否符合预期。
- 数值列统计中的 `count`、`mean`、`min`、`max`、`sum` 是否正确。
- 文本高频值是否与数据分布一致。
- 图表标题、坐标轴和数据是否对应分析结果。

当前阶段主要依赖人工验收和轻量测试，后续可以加入固定样例数据和精确断言。

## 2. RAG 检索效果评估

PDF RAG 检索可以从以下角度评估：

- 检索片段是否与用户问题相关。
- 返回页码是否与 PDF 原文页码一致。
- 引用片段是否真实存在于 PDF 文本中。
- 检索分数排序是否符合直觉。
- `auto` 模式在 TF-IDF 检索失败时是否能回退关键词检索。
- LLM 回答是否只基于检索结果，不编造不存在的页码、文件名或引用。
- 无结果时是否明确说明“未找到相关内容”，而不是假装回答。

当前 RAG 使用关键词和轻量 TF-IDF 检索，适合演示检索链路，不等同于生产级向量数据库效果。当前未接入真实 Embedding 模型和 Chroma/FAISS 向量索引。

## 3. OCR 效果评估

图片 OCR 可以从以下角度评估：

- 中文识别准确率。
- 英文识别准确率。
- 数字、标点和表格截图识别效果。
- 图片清晰度、字体大小、旋转角度、压缩质量对识别结果的影响。
- 扫描件、手写体和复杂背景下的失败情况。
- OCR 引擎缺失或语言包缺失时，是否返回清晰中文提示。

当前 OCR 基于 pytesseract 和本机 / 容器环境中的 Tesseract，不做复杂图像理解、版面分析和 OCR 纠错。

## 4. Agent 工作流评估

Agent 工作流可以从以下角度评估：

- 任务分类是否正确，例如数据分析、图表生成、PDF 问答、图片 OCR、报告生成、多文件综合分析。
- Planner 生成的步骤是否和任务类型匹配。
- Router 是否选择了正确工具。
- Executor 是否只调用预设安全工具。
- Writer 是否能把工具结果整理成中文可读回答。
- 执行轨迹是否完整记录 `classify_task`、`plan_task`、`route_tools`、`execute_tool`、`write_result`、`save_result`。
- 失败节点是否能通过 `error_message` 定位。
- LLM 不可用时，规则分类和模板回答 fallback 是否生效。

当前 Agent 是任务型 Agent，不是开放式自主 Agent。这个限制是有意设计，用于保证安全和可解释性。

## 5. 部署效果评估

部署效果可以从以下角度评估：

- Render 后端冷启动时间是否可接受。
- Render `/api/health` 是否稳定返回。
- Render `/docs` 是否可以打开。
- Vercel 前端是否可以正常加载。
- `VITE_API_BASE_URL` 是否指向正确 Render 后端。
- `CORS_ORIGINS` 是否包含真实 Vercel 前端域名。
- 免费部署环境下上传、分析、RAG、报告功能是否能完成基本演示。
- SQLite 和本地 storage 的临时存储限制是否已在文档中说明。

## 6. 当前限制

- 当前不是生产级评估体系。
- 没有大规模 benchmark。
- 没有真实用户反馈闭环。
- 没有自动化 RAG 准确率评估。
- 没有 OCR 准确率量化数据。
- 免费部署环境存在冷启动、临时存储和资源限制。
- LLM API 调用受网络、Key、模型稳定性和成本影响。

## 7. 后续评估增强方向

- 建立固定测试集，包括表格、PDF、图片和多文件任务。
- 对表格分析结果增加自动化断言。
- 对 RAG 增加问题、期望页码、期望引用片段的评估集。
- 对 OCR 增加样例图片和人工标注文本。
- 对 Agent 分类和路由增加回归测试。
- 记录线上演示错误案例，用于后续迭代。
