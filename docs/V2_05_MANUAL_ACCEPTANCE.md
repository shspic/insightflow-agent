# V2-05 手动验收

## 准备

1. 复制 `.env.example` 为本地 `.env`，不要提交。
2. 备份真实 `backend/data/app.db`。
3. 手动执行 `alembic upgrade head`。
4. 分别启动 API、Worker 和前端。

## 报告与反馈

1. 创建包含表格与规则 Markdown/PDF 的工作区并完成任务。
2. 确认任务完成后出现 v1 报告，模板和 Quality Review 状态可见。
3. 分别导出 Markdown、DOCX、PDF；检查章节、表格、图表、引用、风险、建议和限制。
4. 再次导出同一格式，确认复用同一资产而非无限新增。
5. 选择另一个模板并复用分析重新生成；确认生成 v2，v1 保留。
6. 选择历史报告并设为当前版本，刷新页面后确认服务端仍保留该选择。
7. 提交点赞，确认任务不重新执行。
8. 提交数字错误和纠正说明后重新生成；确认原报告保留。
9. 尝试删除当前版本和唯一版本，应被拒绝；历史版本可进入待清理状态。
10. 使用第二个普通用户访问报告、导出和资产 URL，应返回 404 或拒绝。

## 扫描 PDF OCR

1. 上传同时包含文本页和扫描页的 PDF。
2. 执行文件理解，确认只对低文本页 OCR。
3. 检查 Profile 中候选页、成功页、partial 与置信度。
4. 停止 Tesseract 后重试，确认原 Profile 不被删除且出现清晰降级提示。
5. 检查日志中没有完整 OCR 文本。

## 配额与监控

1. 在测试环境降低每日任务、模型、工具、存储和导出阈值。
2. 逐项达到上限，确认服务端返回 429、当前用量、上限和重置时间。
3. 管理员设置带过期时间和备注的覆盖，确认审计日志存在。
4. 打开个人使用量页，确认刷新后与服务端一致。
5. 打开管理员页，检查任务、Worker、Agent、工具、模型、反馈和 Prompt 版本。
6. 停止 Worker 超过 `WORKER_STALE_SECONDS`，确认 readiness 变为 not_ready。

## 评估、清理和备份

1. 运行 deterministic 评估，确认 85 条、模型调用数为 0、结果持久化。
2. 按类别运行并导出失败案例。
3. 执行 cleanup dry-run，确认文件和数据库未变化。
4. 准备一个过期测试 Session，再显式 apply，确认只删除目标。
5. 创建备份，校验 manifest、SHA-256、SQLite integrity 和 storage 归档。
6. 恢复到一个不存在的新路径；尝试恢复到已有路径必须失败。

## 生产门禁

用隔离环境设置 `ENV=production`，逐项验证弱 Secret、不安全 Cookie、Legacy V1、测试数据库、`DEBUG=true`、通配 CORS、未信任代理、未启用 HSTS、无效配额会拒绝启动。不得在真实环境故意写入弱密钥。

## 仍需人工判断

- DOCX/PDF 的中文字体、分页、宽表和图表清晰度；
- OCR 对目标真实扫描质量的可接受程度；
- 报告用语和免责声明；
- 配额默认值、数据保留期、RPO/RTO；
- 下一阶段视觉层级、移动端和无障碍体验。
