\# 1. 项目概述



\## 1.1 项目名称



\*\*InsightFlow Agent：多模态文档与数据分析智能体\*\*



\---



\## 1.2 一句话定位



InsightFlow Agent 是一个支持 Excel、CSV、PDF、图片上传的 AI Agent 平台，用户可以通过自然语言让系统自动完成文件解析、数据分析、RAG 检索、图表生成、报告输出和执行轨迹展示。



\---



\## 1.3 项目核心定位



本项目不是普通聊天机器人，而是一个\*\*任务执行型 AI Agent 系统\*\*。



普通聊天机器人主要回答问题；InsightFlow Agent 要完成的是：



```text

读取文件 → 理解任务 → 拆解步骤 → 调用工具 → 执行分析 → 生成图表 → 形成报告 → 保存历史 → 展示执行轨迹

```



项目重点体现：



1\. AI Agent 工作流；

2\. 多模态文件处理；

3\. RAG 文档检索；

4\. Pandas 数据分析；

5\. 工具调用；

6\. LangGraph 状态流转；

7\. FastAPI 后端工程；

8\. React 前端展示；

9\. SQLite 历史记录；

10\. Docker 和低成本部署。



\---



\# 2. 项目背景



\## 2.1 背景说明



大量学生、职场新人、运营人员和轻量办公用户经常面对以下文件：



1\. Excel 表格；

2\. CSV 数据；

3\. PDF 文档；

4\. 图片截图；

5\. 调查问卷；

6\. 业务报表；

7\. 课程设计资料；

8\. 用户反馈数据。



这些文件通常包含有价值的信息，但普通用户往往存在以下问题：



1\. 不会写 Python 或 SQL；

2\. 不熟悉 Excel 数据分析；

3\. 不会从 PDF 中快速定位信息；

4\. 不知道如何生成图表；

5\. 不会组织分析报告；

6\. 不清楚分析结论是否有依据；

7\. 使用普通大模型时，无法稳定完成完整任务流程。



现有大模型可以回答问题，但通常不能稳定完成：



```text

文件读取 + 数据分析 + 文档检索 + 图表生成 + 报告输出 + 引用来源 + 执行过程记录

```



因此，本项目设计一个基于 Agent 工作流的多模态文档与数据分析平台，让用户通过自然语言驱动完整的数据与文档处理流程。



\---



\## 2.2 项目要解决的问题



| 问题            | 本项目解决方式                           |

| ------------- | --------------------------------- |

| 用户不会写代码分析数据   | 使用自然语言输入任务，由 Agent 调用 Pandas 工具分析 |

| PDF 文档信息难查找   | 使用 RAG 检索并返回引用来源                  |

| 表格数据难以总结      | 自动生成字段概况、缺失值统计、描述性统计              |

| 分析结果难以展示      | 自动生成柱状图、折线图、饼图等图表                 |

| 结果不方便提交或分享    | 自动生成 Markdown 分析报告                |

| 普通 AI 回答过程不可见 | 前端展示 Agent 执行轨迹                   |

| 项目容易变成聊天 Demo | 强调工具调用、任务流和可验证输出                  |

\# 6. 核心用户场景



\## 6.1 场景一：Excel 数据分析



\### 用户操作



用户上传一个销售数据 Excel 文件，然后输入：



```text

帮我分析各月份销售额变化，找出增长最快的品类，并生成图表和总结。

```



\### 系统执行



系统需要完成：



1\. 解析 Excel；

2\. 识别字段；

3\. 生成数据概况；

4\. 判断任务属于数据分析；

5\. 生成分析计划；

6\. 调用 Pandas 工具统计；

7\. 生成折线图或柱状图；

8\. 输出分析结论；

9\. 保存任务记录；

10\. 展示执行轨迹。



\### 输出结果



系统输出：



1\. 数据字段概况；

2\. 月度销售额趋势；

3\. 增长最快的品类；

4\. 对应图表；

5\. 简要分析结论；

6\. Markdown 报告。



\---



\## 6.2 场景二：PDF 文档问答



\### 用户操作



用户上传一份课程设计说明 PDF，然后输入：



```text

这份文件里关于工程量计算依据的内容有哪些？请引用来源。

```



\### 系统执行



系统需要完成：



1\. 解析 PDF 文本；

2\. 按页码保存文本；

3\. 对文档进行切分；

4\. 生成向量；

5\. 存入向量库；

6\. 根据问题执行 RAG 检索；

7\. 生成回答；

8\. 返回引用页码或片段来源。



\### 输出结果



系统输出：



1\. 回答内容；

2\. 引用页码；

3\. 引用片段；

4\. 检索记录；

5\. Agent 执行轨迹。



\---



\## 6.3 场景三：图片识别与分析



\### 用户操作



用户上传一张表格截图，然后输入：



```text

识别这张图片里的表格内容，并总结主要数据。

```



\### 系统执行



系统需要完成：



1\. 接收图片；

2\. 使用 OCR 或 VLM 识别文字；

3\. 将识别结果转换成结构化文本；

4\. 判断是否能进一步分析；

5\. 如果能分析，则调用数据分析工具；

6\. 如果不能分析，则输出文字摘要；

7\. 保存识别结果和任务记录。



\### 输出结果



系统输出：



1\. 图片识别文本；

2\. 表格摘要；

3\. 主要数据说明；

4\. 识别限制说明；

5\. 执行轨迹。



\---



\## 6.4 场景四：自动生成综合报告



\### 用户操作



用户上传 Excel 和 PDF，然后输入：



```text

根据这些资料生成一份分析报告，包括数据概况、关键发现、图表和建议。

```



\### 系统执行



系统需要完成：



1\. 识别多个文件类型；

2\. 对 Excel 执行统计分析；

3\. 对 PDF 执行 RAG 检索；

4\. 合并表格分析结果和文档上下文；

5\. 生成结构化报告；

6\. Reviewer Agent 检查结论是否有依据；

7\. 输出最终 Markdown 报告；

8\. 保存报告和历史记录。



\### 输出结果



系统输出：



1\. 分析报告；

2\. 图表；

3\. 文档依据；

4\. 风险与限制；

5\. 结论与建议；

6\. 可下载报告文件。

\# 7. 功能模块设计



\## 7.1 模块一：文件上传与管理



\### 7.1.1 功能说明



用户可以上传 Excel、CSV、PDF、图片文件，系统保存文件并记录元数据。



\---



\### 7.1.2 支持文件格式



| 文件类型             | 首版支持 | 处理方式              |

| ---------------- | ---- | ----------------- |

| `.xlsx`          | 支持   | openpyxl / pandas |

| `.csv`           | 支持   | pandas            |

| `.pdf`           | 支持   | PyMuPDF           |

| `.png`           | 支持   | OCR / VLM         |

| `.jpg` / `.jpeg` | 支持   | OCR / VLM         |

| `.docx`          | 后续支持 | python-docx       |

| `.txt` / `.md`   | 可选支持 | 直接读取              |



\---



\### 7.1.3 文件上传限制



首版限制：



1\. 单文件大小不超过 10MB；

2\. 只允许白名单文件类型；

3\. 文件名需要做安全处理；

4\. 文件保存到指定目录；

5\. 文件路径不直接暴露真实系统路径；

6\. 上传失败需要返回明确错误信息。



\---



\### 7.1.4 文件状态



| 状态          | 含义      |

| ----------- | ------- |

| pending     | 已上传，待解析 |

| parsed      | 解析成功    |

| failed      | 解析失败    |

| indexed     | 已完成向量入库 |

| unsupported | 文件格式不支持 |



\---



\### 7.1.5 验收标准



文件上传模块完成时，应满足：



1\. 用户可以通过前端上传文件；

2\. 后端能保存文件；

3\. 数据库能记录文件信息；

4\. 前端能显示文件列表；

5\. 文件类型不合法时会拒绝；

6\. 文件过大时会拒绝；

7\. 上传结果包含 file\_id、filename、file\_type、status。

\## 7.2 模块二：文件解析模块



\## 7.2.1 Excel / CSV 解析



\### 功能说明



系统读取 Excel / CSV 文件，生成数据概况。



\### 解析内容



需要识别：



1\. 字段名；

2\. 行数；

3\. 列数；

4\. 数值列；

5\. 文本列；

6\. 日期列；

7\. 缺失值；

8\. 简要统计信息；

9\. 前若干行预览数据。



\### 输出示例



```json

{

&#x20; "columns": \["month", "category", "sales", "profit"],

&#x20; "row\_count": 1200,

&#x20; "column\_count": 4,

&#x20; "numeric\_columns": \["sales", "profit"],

&#x20; "date\_columns": \["month"],

&#x20; "text\_columns": \["category"],

&#x20; "missing\_values": {

&#x20;   "sales": 3,

&#x20;   "profit": 0

&#x20; }

}

```



\### 验收标准



1\. 能成功解析 `.xlsx`；

2\. 能成功解析 `.csv`；

3\. 能识别行数和列数；

4\. 能识别字段名；

5\. 能识别数值列；

6\. 能统计缺失值；

7\. 解析结果能保存到数据库或任务上下文。



\---



\## 7.2.2 PDF 解析



\### 功能说明



系统提取 PDF 文本，并为后续 RAG 检索做准备。



\### 解析内容



需要完成：



1\. 按页提取文本；

2\. 保存页码；

3\. 对文本进行分块；

4\. 生成 chunk；

5\. 保存 chunk 到数据库；

6\. 后续生成向量并存入向量库。



\### 验收标准



1\. 能上传 PDF；

2\. 能提取 PDF 文本；

3\. 能按页码保存内容；

4\. 能将 PDF 文本切分成 chunk；

5\. 后续 RAG 回答能返回引用页码。



\---



\## 7.2.3 图片解析



\### 功能说明



系统对图片进行 OCR 或 VLM 识别。



\### 首版策略

2\. 文字识别；

3\. 简单表格识别；

4\. 识别结果保存；

5\. 基于识别文本生成摘要。



\### 验收标准



1\. 能上传图片；

2\. 能保存图片文件；

3\. 能调用 OCR 或 VLM 识别文字；

4\. 能展示识别结果；

5\. 能把识别结果交给 Agent 使用。

\## 7.5 模块五：LangGraph 工作流



\### 功能说明



使用 LangGraph 管理 Agent 状态、节点执行、工具调用和结果保存。



\---



\### 推荐工作流



```text

User Input

&#x20;  ↓

Task Classifier

&#x20;  ↓

Planner Agent

&#x20;  ↓

File Context Loader

&#x20;  ↓

Tool Router

&#x20;  ├── Excel / CSV Analysis Tool

&#x20;  ├── PDF RAG Tool

&#x20;  ├── Image OCR Tool

&#x20;  ├── Chart Tool

&#x20;  └── Report Tool

&#x20;  ↓

Reviewer Agent

&#x20;  ↓

Final Response

&#x20;  ↓

Save Task History

```



\---



\### 节点设计



| 节点                | 职责          |

| ----------------- | ----------- |

| classify\_task     | 判断任务类型      |

| plan\_task         | 生成执行计划      |

| load\_files        | 加载文件信息和解析结果 |

\# 13. 非功能需求



\## 13.1 性能需求



首版不做高并发。



目标：



1\. 单文件不超过 10MB；

2\. Excel 不超过 5 万行；

3\. 单次任务尽量控制在 60 秒以内；

4\. 支持 1～5 个朋友低频体验；

5\. 前端页面操作无明显卡顿；

6\. 后端接口错误时能返回明确错误信息。



\---



\## 13.2 安全需求



必须满足：



1\. 不允许执行用户提供的原始 Python 代码；

2\. Pandas 分析只能通过预设工具函数；

3\. 上传文件限制大小和类型；

4\. API Key 放在 `.env`；

5\. `.env` 不提交 GitHub；

6\. 文件路径做隔离；

7\. 生产环境关闭 debug；

8\. 不暴露本地真实文件路径；

9\. 删除文件需要明确指定文件 ID；

10\. 不允许批量危险删除。



\---



\## 13.3 成本需求



首版尽量低成本：



1\. SQLite 本地数据库；

2\. 本地文件存储；

3\. 免费向量库 Chroma / FAISS；

4\. 低价模型 API；

5\. 前端使用 Vercel 免费部署；

6\. 后端使用 Render 或其他低成本平台；

7\. 先保证演示，不追求企业级稳定性。



\---



\## 13.4 可维护性需求



1\. 后端按 api、services、models、schemas 分层；

2\. 不把业务逻辑全部写进路由函数；

3\. Agent 相关代码集中放在 agents 目录；

4\. 配置统一从 `.env` 读取；

5\. 新接口需要在 README 或接口文档中说明；

6\. 关键函数尽量有简单测试；

7\. 每阶段完成后进行 Git commit。

\# 23. 风险与应对



\## 23.1 风险一：项目范围过大



\### 表现



想一次性做完所有功能，导致项目长期无法跑通。



\### 应对



按阶段开发：



```text

先跑通 Excel / CSV 分析 → 再做 Agent → 再做 RAG → 再做图片 → 最后做部署和 MCP

```



\---



\## 23.2 风险二：Agent 变成伪 Agent



\### 表现



项目只是调用一次大模型回答问题，没有真正工具调用和执行流程。



\### 应对



必须实现：



1\. 任务分类；

2\. 执行计划；

3\. 工具调用；

4\. 工具调用记录；

5\. 执行轨迹展示。



\---



\## 23.3 风险三：Pandas 分析不安全



\### 表现



让大模型生成 Python 代码并执行，存在安全风险。



\### 应对



只允许调用预设分析函数，不执行用户代码。



\---



\## 23.4 风险四：RAG 效果不稳定



\### 表现



回答不准确，引用来源不清楚。



\### 应对



首版先保证：



1\. PDF 能分块；

2\. 能检索；

3\. 能返回引用片段；

4\. 回答中明确说明依据来源。



\---



\## 23.5 风险五：部署成本过高



\### 表现



项目依赖过多，免费平台难部署。



\### 应对



首版优先：



1\. SQLite；

2\. 本地文件存储；

3\. 轻量向量库；

4\. 低价模型 API；

5\. 前后端分开部署。

1\. 不只是聊天机器人；

```text

```



首要目标不是一开始就做大，而是先完成：



```text

上传文件 → 解析数据 → 输入任务 → 调用工具 → 生成图表 → 输出报告 → 保存历史

```



在这个闭环完成后，再增加：



```text

LangGraph → PDF RAG → 图片 OCR → 执行轨迹 → Docker → 部署 → MCP

```



这样项目既能落地，也能逐步强化简历竞争力。
