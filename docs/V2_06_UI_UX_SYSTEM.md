# V2-06 全站 UI、交互、响应式与可访问性系统

## 1. 阶段边界

V2-06 只重构现有 V2-02 至 V2-05 前端体验，不增加后台业务能力，也不改变 Cookie Session、CSRF、工作区隔离、任务队列、SSE、报告下载和管理员权限规则。

实现以当前 FastAPI 路由、Pydantic Schema 和状态枚举为准。当前接口没有提供的数据不会由前端伪造。例如工作区列表不虚构“最近任务状态”，任务列表也不虚构模板、降级和质量字段；需要这些信息时进入真实详情接口。

本阶段没有引入新的 npm 依赖，没有使用远程字体、CDN 或外部图片，也没有使用 `dangerouslySetInnerHTML`。

## 2. 设计原则

- 专业、克制、现代，以资料、任务状态和操作效率为中心。
- 默认浅色，支持深色与跟随系统。
- 保持较高信息密度，但通过分区、层级和渐进披露避免拥挤。
- 状态同时使用文字、图形和颜色，不把颜色作为唯一信息。
- 危险操作明确确认；字段错误靠近字段；需要处理的错误不只用 Toast。
- 服务端始终是任务和权限状态的真相来源。

## 3. 设计 Token

设计变量集中在 `frontend/src/styles/tokens.css`，组件不再散落维护主题颜色和基础间距。

| 类别 | 内容 |
| --- | --- |
| 背景 | 页面、侧栏、表面、浮层、弱化层 |
| 文字 | 主文字、次文字、弱文字、反色文字 |
| 边框 | 默认、强调、焦点环 |
| 状态 | 品牌、成功、警告、危险、信息及其弱背景 |
| 尺寸 | 4px 基准间距、圆角、控件高度、内容宽度 |
| 排版 | 系统字体栈、字号、行高、报告阅读宽度 |
| 视觉 | 轻量阴影、短过渡、统一 Z-index |
| 响应式 | 360px、768px、1024px、1440px 验收基准；960px 为主导航切换点 |

深色主题通过根节点 `data-theme` 覆盖同一组语义变量；“跟随系统”通过 `prefers-color-scheme` 解析。只在 `localStorage` 保存非敏感主题偏好。

## 4. 公共组件体系

统一组件位于 `frontend/src/components/common/`：

- 操作：`Button`、`IconButton`、`Dropdown`。
- 表单：`Input`、`Textarea`、`Select`、`Checkbox`、`Switch`、`FormField`、`PasswordField`。
- 容器：`Card`、`Dialog`、`Drawer`、`Tabs`、`Tooltip`。
- 状态：`Badge`、`StatusBadge`、`Alert`、`Skeleton`、`Spinner`、`Progress`、`Stepper`。
- 反馈：`Toast`、`ConfirmDialog`、`EmptyState`、`ErrorState`。
- 页面：`PageHeader`、`SectionHeader`、`Pagination`。
- 内容：`SafeMarkdown`，只把 Markdown 解析为 React 文本节点，不渲染不可信 HTML。

公共组件统一支持 disabled、loading、错误提示和 `focus-visible`。`Dialog` 支持初始焦点、Tab 焦点约束、Escape 关闭和关闭后焦点恢复。

## 5. 全局布局与信息架构

桌面端采用可折叠左侧导航、顶部上下文栏和主内容区；移动端改为顶部栏和抽屉导航。管理员入口只向管理员展示。退出、主题和个人信息归入统一菜单。

主要路由：

- `/workspaces`：工作区列表。
- `/workspaces/:workspaceId`：工作区概览。
- `/workspaces/:workspaceId/files`：文件。
- `/workspaces/:workspaceId/relations`：文件关系。
- `/workspaces/:workspaceId/context`：Workspace Context。
- `/workspaces/:workspaceId/new-analysis`：新建分析。
- `/workspaces/:workspaceId/tasks`：任务历史。
- `/workspaces/:workspaceId/tasks/:taskId`：任务执行详情。
- `/workspaces/:workspaceId/reports`：报告列表。
- `/workspaces/:workspaceId/reports/:taskId`：报告中心。
- `/workspaces/:workspaceId/settings`：设置。
- `/usage`、`/admin`、`/403` 和兜底 404。

`must_change_password` 仍由路由守卫强制执行，不能通过导航绕过。Session 失效由认证上下文统一处理。

## 6. 核心用户流程

### 6.1 认证

登录只显示账号和密码；注册显示账号、密码、确认密码和邀请码；密码重置使用不会暴露账号是否存在的统一说明；强制改密解释触发原因。密码字段可显示或隐藏，提供实时最低要求与一致性检查，提交时防止重复请求。

### 6.2 工作区

工作区列表支持搜索、状态筛选、创建、编辑、归档、恢复和软删除。首次加载使用 Skeleton，空状态提供创建入口，配额接近上限时显示页面内警告。

工作区详情由超长页面拆为稳定子路由。概览只展示真实可用的说明、文件状态、文件类型、关系数量、最近任务、当前配额和快捷入口。

### 6.3 文件上传与理解

批量上传采用拖拽区和文件队列，上传前显示支持类型、单文件大小和批量数量限制。每个文件独立校验、上传、失败和重试，不让单个失败阻断整批。成功后明确引导理解。

文件页支持搜索、类型/状态/角色筛选、多选、批量理解、删除、关系发现和创建分析。Profile 使用折叠结构展示摘要、结构、质量、角色、标签、模型降级和版本，不直接铺开大型 JSON，也不显示服务器路径。

文件关系以桌面表格和移动卡片呈现 suggested、confirmed、rejected。置信度显示为“匹配分”，避免误导成准确率；证据、状态和备注均可读。

### 6.4 新建分析、追问和计划确认

流程被组织为：

```text
选择文件 → 输入目标 → 输出偏好 → Agent 追问 → 计划确认 → 开始执行
```

文件状态、角色、质量和关系风险会在选择阶段提示。追问显示问题与需要原因。计划以步骤列表展示 Agent、工具、依赖、输入、假设、风险和调用估计，支持顺序调整和可选步骤删除；不允许编辑原始 JSON、Prompt 或注册表之外的工具。计划校验失败会保留当前编辑内容。

## 7. Agent 实时执行体验

任务详情显示状态、总体进度、当前阶段、耗时、Worker 提示、连接方式、取消/重试入口、步骤状态和事件时间线。

- SSE 仍是首选，使用 Cookie 同域凭证和 Last-Event-ID。
- SSE 断开后先显示重连状态，再降级为 2.5 秒轮询。
- 同一页面只保留一个 SSE；切换页面会清理连接和计时器。
- 事件按 ID 合并去重，界面最多保留最近 300 条，避免长任务持续膨胀。
- 终态关闭 SSE 并停止无意义轮询。
- 页面刷新通过任务详情和事件接口恢复，不在浏览器持久存储任务真相。
- 浏览器关闭不会取消服务端任务；取消提示说明不可中断库调用采用协作式取消。

内部 Agent 统一显示中文名称，技术名放在补充信息中。技术错误默认折叠。

## 8. 报告阅读与交付

桌面报告中心采用目录/版本、正文、引用与资产三栏；中等宽度收敛为两栏；移动端为版本操作、折叠目录、正文和资产对话框。

- 版本按真实版本号和时间排序，可切换当前版本、删除历史版本。
- Markdown 采用安全结构化渲染，标题可定位，表格局部横向滚动，代码和 JSON 默认折叠。
- Quality Review、警告、生成时间、模板和当前版本独立显示。
- 图表可放大，并提供文本摘要和替代文本。
- Markdown、DOCX、PDF 均走鉴权下载接口；前端使用 Blob 下载并释放对象 URL。
- 反馈必须先选择问题类型，再填写说明；重新生成明确说明旧版本保留和配额影响。

## 9. 使用量与管理员信息架构

使用量页面用具体数值和进度条展示任务、模型调用、工具调用、运行任务、文件/报告存储及工作区数量。达到 80% 时预警；管理员豁免同时显示系统安全上限。

管理员页拆为用户、邀请码、密码重置、审计和运行治理。运行治理再分系统、任务、Worker、模型、反馈、Prompt、评估和清理。高风险操作使用统一确认；邀请码和临时密码只在专门对话框显示一次，关闭后从前端状态清除。管理员页面不展示普通用户原始文件或完整报告正文。deterministic 评估明确标注为规则自检。

## 10. 全局加载、空状态和错误

`mapApiError` 把 API 错误统一为用户可理解标题、原因、建议和可复制的技术标识。首次加载使用 Skeleton；空工作区、文件、任务、报告和反馈均使用带下一步操作的 EmptyState。

成功操作使用 5 秒 Toast，并通过 `aria-live` 宣告；权限、配额、Worker、DeepSeek、OCR、SSE 和服务降级等需要处理的状态使用页面内 Alert 或 ErrorState。后端堆栈不会显示。

## 11. 响应式与无障碍

- 360px：单列布局、移动抽屉、底部 Sheet/全屏 Dialog、可换行操作栏。
- 768px：认证页、报告和管理页降低栏数，数据表局部滚动。
- 1024px：保留工作台导航，报告收敛为两栏。
- 1440px：使用受控最大内容宽度，避免表单和正文过度拉伸。
- 表格横向滚动只发生在表格容器，不制造页面级横向滚动。
- 长文件名截断并保留可访问完整名称。
- 使用语义化按钮、链接、label、`aria-label`、`aria-live`、skip link 和明确焦点环。
- 状态不只靠颜色，图表有文本摘要。
- 遵循 `prefers-reduced-motion`，关闭非必要过渡。

## 12. 性能与稳定性

- 路由级 `React.lazy` 和 `Suspense` 拆分首屏。
- 任务事件去重并限制数量，终态停止连接和轮询。
- 工作区概览并行读取已有 API，局部更新工作区列表，减少整页刷新。
- 任务列表客户端分页；大型表格局部滚动；报告正文按结构块渲染。
- 不把敏感结果、Token、密码、邀请码或任务状态存入持久浏览器存储。
- 不因组件卸载取消服务端任务。

## 13. API 与国内同域部署入口

默认 API 基址仍是相对 `/api/v2`，本地由 Vite `/api` Proxy 转发。`VITE_API_BASE_URL` 只作为兼容覆盖，不在业务组件写死 localhost、Vercel 或 Render。

国内同域部署时建议：

1. 前端静态资源与后端放在同一站点；
2. 反向代理 `/api` 到 FastAPI，并关闭 SSE 响应缓冲；
3. 保留 Cookie、CSRF、CORS/同域和代理可信头配置；
4. 为 SSE 增加足够的读超时并传递 `Last-Event-ID`；
5. 校验 DOCX/PDF 下载响应头和大文件超时；
6. 不需要修改前端业务组件，只在构建或代理层设置 API 基址。

本阶段不进行国内云部署、域名/DNS、PostgreSQL 或对象存储迁移。

## 14. 测试与验证范围

纯逻辑测试位于 `frontend/src/utils/ui.test.js`，覆盖状态文案、错误映射、配额预警、计划校验、SSE 合并去重、报告版本排序、文件类型、权限导航、一次性秘密状态和主题读取。

真实浏览器抽查覆盖登录页桌面、360px 移动端、768px 深色主题和键盘焦点。需要认证和真实任务数据的页面仍应按 `V2_06_MANUAL_ACCEPTANCE.md` 完成业务手动验收，不能把构建成功等同于完整视觉验收。

## 15. 当前限制

- 工作区与任务列表仅展示现有列表 API 返回的数据；更丰富摘要需要未来向后兼容的聚合接口。
- 大型任务事件采用数量上限而非虚拟列表。
- 长报告采用结构块渲染，没有引入虚拟化依赖。
- 文件上传的浏览器进度受当前请求实现限制，不能等同于服务端解析/理解进度。
- 移动端管理员功能优先保证查看和核心操作，不追求桌面表格密度。
- 本阶段没有完整的自动化 E2E；登录页外的真实业务流程依赖人工测试账号、Worker 和样例文件验收。
